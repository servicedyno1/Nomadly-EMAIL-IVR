  ```
  [TTS] Falling back to ElevenLabs Rachel...
  [TTS] Fallback ElevenLabs Rachel also failed: Request failed with status code 402
  [BulkTTS] TTS error: Both openai and elevenlabs failed ... 402 ...
  ```

## Root cause
- ALL TTS (both "OpenAI" and "ElevenLabs" voices) goes through ONE EdenAI endpoint
  (`js/tts-service.js:164` → `https://api.edenai.run/v2/audio/text_to_speech`) with ONE `EDENAI_API_KEY`.
- That EdenAI key is out of credits. Direct probe from the dev pod:
  `GET /v2/cost_management/credits/` and a 2-char TTS POST both return
  `HTTP 402 {"Not enough credits":"You don't have enough credits left with your access token. Use another access token."}`
- Same key fingerprint (sha256 f0159ee7ebb0…) in `/opt/nomadly/shared/{app-main,app-wl,app-voodoo}/backend.env` and the vault
  → ALL 3 brands (Nomadly, SMADAV, Voodoo) are affected; Voodoo was just the first to hit it.
- Timeline: last successful TTS 2026-10-15T07:33:25Z, first 402 at 17:13:03Z. Volume is low (≈1–8 clips/day) — the balance simply ran dry.
- The built-in "fallback to the other provider" can never help here: both providers bill the same EdenAI account.
- `balance-monitor.js` alerts admins for Telnyx/Twilio only — EdenAI is not monitored, so a customer found it first.

## Blast radius
- BROKEN: every NEW TTS generation — Quick IVR (`_index.js:26680`, msg cp_104), Bulk IVR (`:27902`, cp_207),
  Audio Library TTS (`:31175`, `:31865`, `:32880`), IVR greeting (`:32327`), inbound IVR template API (`:42510`),
  OTP prompt warm-up (`tts-service.js ensureOtpPrompt`).
- NOT affected: live calls (use cached / pre-generated audio; `getCachedOtpPrompt` is cache-only), user-uploaded audio.

## Secondary UX bugs found
1. cp_104/cp_207 tell users "Try ElevenLabs — it tends to be more reliable" (false: same backend) and leak raw
   "Request failed with status code 402" text; cp_104 passes `err.message` unsanitized; error ends with
   "Please try again in a moment" (retrying never helps on 402).
2. axios hides EdenAI's response body — logs show only "status code 402", not "Not enough credits".
3. ElevenLabs speed (e.g. 0.5x) is silently ignored via EdenAI.

## Proposed fix
A. Immediate (ops, no deploy): top up EdenAI credits (app.edenai.run → Billing) or raise the token's credit cap.
   Same token → works instantly. New token → update `EDENAI_API_KEY` in the 3 `/opt/nomadly/shared/*/backend.env`
   + vault, then `pm2 reload app-main-a app-wl-b app-voodoo-b --update-env` (key is read once at module load, tts-service.js:10).
B. Code hardening (pending owner approval):
   1. `tts-service.js`: classify 401/402/403 as billing/auth → skip same-account cross-provider retry → fall back to
      DIRECT OpenAI TTS (`/v1/audio/speech`, same 6 voices alloy/echo/fable/onyx/nova/shimmer, native speed 0.25–4.0)
      using the already-configured, valid `APP_OPEN_API_KEY` (verified HTTP 200). ElevenLabs voices map to nearest OpenAI voice.
   2. Log `err.response?.data` for EdenAI errors.
   3. `balance-monitor.js`: add EdenAI credit check + throttled admin Telegram alert on first 402 (6h dedup, like Telnyx/Twilio).
   4. Replace cp_104/cp_207 copy: "Voice generation is temporarily unavailable — upload your own recording or try again later.
      Our team has been notified." + Upload Audio button; sanitize cp_104.
